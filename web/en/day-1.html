1. Start with one question: what changes when AI can act?

A language model can generate text. A useful agentic application adds something around the model: a goal, bounded context, approved tools or actions, limits, evidence about what happened, and a point where a human remains responsible.

Generate

“Explain this concept.” The model produces text from the prompt and context.

Recommend

“Suggest which source I should inspect.” The system proposes an action, but does not execute it.

Act through a tool

“Read the approved learning card and use it for one short hint.” The application may execute an allow-listed read-only tool and return the result to the model.

Opening prompt: Which of the three examples above requires the application to do more than generate text? What new risks appear when software can act?

2. From AI to a large language model

Artificial intelligence

A broad category of systems designed to perform tasks associated with perception, prediction, language, reasoning or action selection.

Machine learning

A common way to build AI systems by learning patterns from data rather than encoding every rule manually.

Generative AI

Models that generate new content such as text, code, images or audio from learned statistical patterns and the current input.

Large language model

A generative model specialised for language and related representations. It generates likely continuations from context; it is not automatically a source of truth, a workflow, or an authorised actor.

Why useful answers can still be wrong

An LLM is optimised to generate plausible output, not to guarantee that every statement is supported by an approved source. In education this matters because a polished explanation can still include an unsupported fact, invented citation or overconfident conclusion.

Prompt
What the user asks
Context
What information is available in this turn
Generation
The model predicts a useful response
Verification
The application or human checks evidence and boundaries

3. Model, chatbot, assistant and agent are different layers

Model

The inference engine. It transforms input context into output.

Chatbot

A conversational interface around a model. It manages messages and presents responses.

Assistant

A product that helps a user complete tasks, often with files, context, browsing or other capabilities. In this workshop ChatGPT Plus is a browser-based explanation and coding assistant.

Agentic application

An application that gives the model an explicit role and boundaries, lets it request approved actions/tools, observes results and continues within a controlled workflow.

A practical test: “Can the system do something?”

If a system only produces text, calling it an “agent” may add little meaning. The distinction becomes useful when the application can select from approved actions, execute them under rules, observe the result and continue or stop.

Not enough by itself

Role prompt, long answer, personality, chain of messages, or the word “agent” in the interface.

Agentic signal

Controlled action selection, tool execution, observation of results, explicit limits and traceable evidence.

Still not autonomy without limits

More autonomy is not automatically better. In education, a narrow and inspectable agent is often easier to justify than a highly autonomous one.

4. Minimal anatomy of an educational agent

1 · Goal / instruction
What the agent is allowed and expected to support
2 · User request
The learner or instructor asks for help
3 · Context
Current task, bounded history and allowed information
4 · Model
Interprets the request and chooses the next step
5 · Tool / action
Optional approved operation
6 · Observation
The application receives the tool result
7 · Response / stop
The model responds or the workflow ends
8 · Human control
Review, intervention and responsibility remain explicit

The agent loop

Think → Act → Observe → Continue or Stop. This loop is useful only when every action is bounded. In the workshop starter, the model can request one approved read-only tool, the application executes it, records factual evidence, and returns the result to the model.

Tools are capabilities, not magic

A tool is an operation the application exposes to the model. It can be as narrow as “read this one approved learning card” or as powerful as changing a calendar, sending a message or updating a database. The risk changes with the capability.

Read-only tool

Lower operational impact. Example: retrieve one approved course material by a fixed identifier.

Write/action tool

Higher impact. Example: send, change, publish or delete something. Such actions normally need stronger permissions and approval.

Tool boundary

The model should not gain arbitrary file, URL or system access simply because it asks for it.

Context is not the same as long-term memory

Context is the information available for the current reasoning step: the user request, bounded history, instructions and tool results. Memory is an optional application mechanism that persists information across interactions. The workshop starter relies on bounded context; persistent learner memory is not required.

Levels of autonomy

Level 0
Generate only
Level 1
Suggest an action; human executes
Level 2
Use approved read-only tool
Level 3
Prepare or request a higher-impact action with human approval
Higher autonomy
Out of scope for this pilot

The workshop deliberately stays near the low end of this scale. The goal is to understand the mechanism and control it, not to maximise autonomy.

5. Where agents can help in defence education

The examples below are educational and administrative. They do not require real operational data or autonomous military decision-making.

Guided learner support

A learner writes a first attempt. The agent reads one approved learning source and gives a short hint without replacing the learner’s work.

Instructor preparation

An agent can assemble a draft activity plan from approved course material, while the instructor reviews the pedagogy and final content.

Evidence-bound Q&A

An agent answers questions only from a defined set of public or approved training materials and clearly states when the source is insufficient.

Course workflow support

An agent can help structure routine non-sensitive tasks such as checking a submission against an explicit checklist, while leaving the final judgement to the instructor.

Instructor-only micro-demonstration

  1. Show the prepared Day 3 starter on the instructor machine.
  2. Send one grounded request that requires the approved learning card.
  3. Point out the difference between the model’s text and the factual execution log.
  4. Show the read_course_material call and the fixed material identifier.
  5. Stop. Do not turn Day 1 into participant agent setup or testing.
What participants should notice: the important change is not “the AI sounds smarter.” The application has a controlled capability, evidence of its use, and an explicit boundary.

6. Human control is part of the architecture

Before

Define purpose, allowed data, tools, limits and success criteria.

During

Keep actions inspectable, bound permissions, surface failures and provide a stop/recovery path.

After

Review outputs and logs, test expected failure modes and decide whether the system is acceptable for the intended context.

Safety and data boundary

Use only public, synthetic or otherwise approved material. Do not enter classified/sensitive information, credentials, API keys, private logs or participant personal data into ChatGPT, the learning site, screenshots or shared support channels.

Before using any AI service, ask four questions: What data leaves my device? Where does it go? What can the application do? Who remains responsible?

The practical goal is deliberately limited: make sure Day 2 can start on time. Do not configure or test the agent runtime yet.

python --version
Expected: Python 3.12.x on the primary participant baseline. If another version is installed, record it rather than hiding the difference.

Check Git

git --version
Expected: a Git version string and no command-not-found error.

Check VS Code

code --version
Expected: a VS Code version. If the code command is unavailable but VS Code opens normally, record that as a specific environment difference.

Check repository state

git status --short
Expected: the authorised workshop repository opens locally and you can see dashboard/ and starter/.

Account/access check

  1. Confirm sign-in to ChatGPT Plus, GitHub and Groq. Do not paste API keys into this site or ChatGPT.
  2. Confirm you can open the authorised workshop repository in VS Code.
  3. Locate dashboard/ for Day 2 and starter/ for Days 3–4. Do not modify them today.
  4. Record the final state as READY or BLOCKED: <specific reason> with the next recovery action.

What counts as READY?

Software

Python, Git and VS Code are installed and usable.

Access

You can access ChatGPT Plus, the authorised GitHub repository and your Groq account.

Project visibility

You can open the repository and locate the Day 2 dashboard and Day 3–4 starter.

Known blocker

If something fails, the exact reason and recovery owner/action are written down.
