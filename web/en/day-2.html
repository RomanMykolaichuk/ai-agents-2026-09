Day 2 · 60 minutes · CREATE WITH AI

Vibe Coding and Web Project Basics

Use ChatGPT Plus as a supervised coding assistant on a tiny synthetic-data dashboard. Make two bounded changes, inspect the real repository diff, prove recovery, and prepare the separate educational-agent starter for Day 3.

Canonical participant path · RT-FIX-1
Day 2 boundary: the dashboard is not an agent. Today you practise a controlled software-change workflow. Educational-agent construction starts on Day 3; formal T1–T3 testing belongs to Day 4.

1. Canonical participant path

Where am I?

Use two terminals. Terminal A runs the dashboard server from dashboard/. Terminal B returns to the repository root for Git evidence and recovery.

What do I run?

Use the exact command blocks on this page. Do not guess relative paths and do not run Git recovery commands from an unknown folder.

What should I see?

Baseline: 8 learners, average attempts 1.75, no Completed learners KPI, no follow-up filter. Final accepted practice: KPI 6 and follow-up rows Learner 04 + Learner 07.

If it fails?

Stop and identify the failed layer: folder/path, local HTTP server, browser result, Git state, or Day 3 starter setup. Do not compensate by changing synthetic data or adding new frameworks.

2. Read the four-file project

index.html = structure

Visible page elements: headings, KPI cards, table and controls.

style.css = presentation

Spacing, typography, layout and responsive appearance.

app.js = behaviour

Loads JSON, calculates metrics, filters and renders rows.

data.json = data

Eight fictional learner records. Read them; do not edit them to force the expected answer.

3. Launch the baseline first

Open a terminal inside the repository. Use one of the following exact routes.

Windows PowerShell — Terminal A

Set-Location (git rev-parse --show-toplevel)
Set-Location workshops\ai-agents-defence-education\dashboard
py -3.12 -m http.server 8002 --bind 127.0.0.1

Ubuntu/Linux — Terminal A

cd "$(git rev-parse --show-toplevel)/dashboard"
python3 -m http.server 8002 --bind 127.0.0.1

Open http://127.0.0.1:8002/. PASS baseline if you see Total learners = 8, Average attempts = 1.75, eight rows, status Loaded, and no participant-created KPI/filter.

If data does not load: do not open the page with a file:// URL. Keep the local HTTP server running and reload http://127.0.0.1:8002/.

4. Give ChatGPT the actual project context

ChatGPT cannot see files on your laptop unless you provide them. For this exercise, attach or paste only these current files:

  • index.html
  • style.css
  • app.js
  • data.json
Do not provide: .env, API keys, repository ZIP files, private logs, screenshots containing secrets, or unrelated files. If the required current files have not been provided, ChatGPT should ask for them instead of inventing the project structure.

5. Iteration A — Completed learners

Add one derived KPI named Completed learners. It must be calculated from learner.completed. Expected value: 6.

  1. Provide the four current dashboard files to ChatGPT.
  2. Use the canonical Iteration A prompt below.
  3. Ask ChatGPT to name the files it proposes to change before showing code.
  4. Reject hard-coding, changes to data.json, framework migration, backend/database/package/library additions, and unrelated refactoring.
  5. Apply only the accepted minimal change manually in VS Code.
  6. Refresh and verify Completed learners = 6.

6. Iteration B — Needs follow-up filter

Provide ChatGPT with the current post-Iteration-A versions of any files that changed. Add one control labelled Show learners needing follow-up. Filter criterion: completed === false. Expected rows: Learner 04 and Learner 07. The control must allow returning to all eight learners.

  1. Use the canonical Iteration B prompt below.
  2. Prefer one visible control in index.html plus a small extension of the existing render/filter logic in app.js.
  3. Verify default view = 8 rows.
  4. Activate the filter and verify exactly Learner 04 + Learner 07.
  5. Return to all learners and verify 8 rows again.

7. Evidence and recovery — always from repository root

Keep Terminal A running. Open Terminal B inside the repository and first return to the repository root. Then inspect, save, restore and reapply the accepted change.

Windows PowerShell — Terminal B

Set-Location (git rev-parse --show-toplevel)
git status --short
git diff -- dashboard
git diff --output="$env:TEMP\day2-dashboard.patch" -- dashboard
Test-Path "$env:TEMP\day2-dashboard.patch"
git restore --staged --worktree -- dashboard
git status --short
git apply "$env:TEMP\day2-dashboard.patch"
git diff -- dashboard

Ubuntu/Linux — Terminal B

cd "$(git rev-parse --show-toplevel)"
git status --short
git diff -- dashboard
git diff --output=/tmp/day2-dashboard.patch -- dashboard
test -s /tmp/day2-dashboard.patch && echo "patch saved"
git restore --staged --worktree -- dashboard
git status --short
git apply /tmp/day2-dashboard.patch
git diff -- dashboard

After git restore, refresh the browser and confirm the baseline returns. After git apply, refresh again and confirm KPI = 6 and the follow-up filter = 2. The saved patch is the recovery source for this exercise; you do not need to reconstruct accepted changes from memory.

8. Prepare the Day 3 starter

Return to the repository root, enter starter/, prepare the Python environment, and create .env only if it does not already exist.

Windows PowerShell

Set-Location (git rev-parse --show-toplevel)
Set-Location workshops\ai-agents-defence-education\starter
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe verify.py
if (-not (Test-Path .env)) { Copy-Item .env.example .env } else { Write-Host ".env exists; not overwritten" }
git check-ignore -v .env

Ubuntu/Linux

cd "$(git rev-parse --show-toplevel)/starter"
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python verify.py
[ -f .env ] || cp .env.example .env
git check-ignore -v .env

Edit the local .env in VS Code and add your own Groq key there only. Never paste the key into ChatGPT, the workbook, screenshots or shared chat. If time allows, start Uvicorn and check /api/health; this confirms local application health, not credential validity and not Day 3 agent evidence.

9. What counts as Day 2 completion?

Software-change evidence

Baseline works; Iteration A shows 6; Iteration B shows Learner 04 + Learner 07 and can return to all 8.

Review evidence

You can explain which files changed and name at least one proposal you rejected for scope or correctness reasons.

Recovery evidence

You inspected the diff from repository root, saved the accepted patch, restored the baseline, then reapplied and reverified the accepted version.

Day 3 readiness

verify.py passes or has a precise blocker; local .env exists without being overwritten and is ignored by Git.
