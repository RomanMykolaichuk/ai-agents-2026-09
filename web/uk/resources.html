Короткий глосарій

Model

Мовна модель, що генерує відповідь із наданого context. Це лише один компонент agentic application.

Agentic application

Застосунок, що поєднує instructions/context, model, approved actions/tools, observations, limits і human control.

Tool

Можливість, яку application надає model. У core workshop tool read-only та allow-listed.

Grounding

Використання approved source для factual support замість вигаданого evidence.

Factual log

Application evidence того, яка action/tool фактично виконалася. Текст model “я використав джерело” не є рівноцінним доказом.

Bounded change

Навмисно мала зміна з явним scope, expected result, evidence і recovery path.

Checkpoint

Відомий працездатний version/state, який можна ідентифікувати й відновити перед наступною роботою.

Technical error

Runtime/provider failure. Спочатку його потрібно відновити, а вже потім оцінювати behavioural quality.

Instructor required

Стан, коли application навмисно зупиняється, бо configured boundary або schema потребує втручання людини.

Human outcome

Day 4 evidence label: PASS / FAIL / NEEDS REVIEW / BLOCKED: TECHNICAL. Він відокремлений від runtime status.

Support і feedback route

Під час pilot

Для unresolved setup/recovery blockers використовуйте викладача та optional up-to-30-minute post-session support. Передавайте лише non-sensitive command/error state.

Feedback

Organiser-approved participant-facing feedback URL має бути підтверджений до final GO. До цього placeholder або private edit/admin URL не вважається погодженим submission route.

Release rule: якщо external link, provider model, feedback form або support route змінюється до delivery, оновіть delivery-specific evidence, а не припускайте, що старий маршрут все ще працює.
