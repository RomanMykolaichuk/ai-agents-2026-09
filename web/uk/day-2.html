День 2 · 60 хвилин · CREATE WITH AI

Vibe Coding та основи вебпроєкту

Використайте ChatGPT Plus як керованого помічника з кодування для невеликого dashboard на синтетичних даних. Зробіть дві обмежені зміни, перевірте реальний Git diff, доведіть можливість відновлення та підготуйте окремий educational-agent starter до Дня 3.

Канонічний маршрут учасника · RT-FIX-1
Межа Дня 2: dashboard навмисно не є агентом. Сьогодні ви відпрацьовуєте контрольований software-change workflow. Створення educational agent починається у День 3; формальні T1–T3 належать Дню 4.

1. Канонічний маршрут учасника

Де я працюю?

Використовуйте два термінали. Terminal A запускає dashboard server із папки dashboard/. Terminal B повертається в корінь репозиторію для Git evidence та recovery.

Що запускати?

Використовуйте точні command blocks на цій сторінці. Не вгадуйте relative paths і не запускайте Git recovery з невідомої папки.

Що має бути видно?

Baseline: 8 learners, average attempts 1.75, без Completed learners KPI і без follow-up filter. Фінальна practice version: KPI = 6 та follow-up rows = Learner 04 + Learner 07.

Що робити при помилці?

Спершу визначте рівень проблеми: folder/path, local HTTP server, browser result, Git state або Day 3 starter setup. Не компенсуйте помилку зміною synthetic data чи додаванням нового framework.

2. Прочитайте чотири файли проєкту

index.html = структура

Видимі елементи сторінки: headings, KPI cards, table і controls.

style.css = оформлення

Spacing, typography, layout і responsive appearance.

app.js = поведінка

Завантажує JSON, обчислює metrics, фільтрує та формує rows.

data.json = дані

Вісім вигаданих learner records. Їх треба читати, а не змінювати, щоб примусово отримати expected answer.

3. Спочатку запустіть baseline

Відкрийте terminal усередині repository. Використайте один із точних маршрутів нижче.

Windows PowerShell — Terminal A

Set-Location (git rev-parse --show-toplevel)
Set-Location workshops\ai-agents-defence-education\dashboard
py -3.12 -m http.server 8002 --bind 127.0.0.1

Ubuntu/Linux — Terminal A

cd "$(git rev-parse --show-toplevel)/dashboard"
python3 -m http.server 8002 --bind 127.0.0.1

Відкрийте http://127.0.0.1:8002/. Baseline PASS, якщо видно Total learners = 8, Average attempts = 1.75, вісім rows, status Loaded, а participant-created KPI/filter ще відсутні.

Якщо data не завантажується: не відкривайте сторінку через file://. Залиште local HTTP server запущеним і перезавантажте http://127.0.0.1:8002/.

4. Передайте ChatGPT реальний контекст проєкту

ChatGPT не бачить файлів на вашому ноутбуці, доки ви їх не надасте. Для цієї вправи attach або paste тільки поточні:

  • index.html
  • style.css
  • app.js
  • data.json
Не передавайте: .env, API keys, ZIP repository, private logs, screenshots із secrets або unrelated files. Якщо потрібні current files не надані, ChatGPT має попросити їх, а не вигадувати структуру проєкту.

5. Iteration A — Completed learners

Додайте один derived KPI Completed learners. Значення має обчислюватися з learner.completed. Очікуваний результат: 6.

  1. Надайте ChatGPT чотири current dashboard files.
  2. Використайте canonical Iteration A prompt нижче.
  3. Попросіть спочатку назвати files, які пропонується змінити, і лише потім показувати code.
  4. Відхиляйте hard-coding, changes to data.json, framework migration, backend/database/package/library additions і unrelated refactoring.
  5. Вручну застосуйте тільки accepted minimal change у VS Code.
  6. Refresh і перевірте Completed learners = 6.

6. Iteration B — Needs follow-up filter

Надайте ChatGPT current post-Iteration-A versions файлів, які змінилися. Додайте control Show learners needing follow-up. Criterion: completed === false. Очікувані rows: Learner 04 і Learner 07. Має бути можливість повернутися до всіх восьми learners.

  1. Використайте canonical Iteration B prompt нижче.
  2. Очікуйте мінімальний scope: один visible control у index.html + невелике розширення render/filter logic у app.js.
  3. Перевірте default view = 8 rows.
  4. Увімкніть filter і перевірте рівно Learner 04 + Learner 07.
  5. Поверніться до all learners і знову перевірте 8 rows.

7. Evidence і recovery — завжди з кореня repository

Залиште Terminal A запущеним. Відкрийте Terminal B усередині repository та спочатку поверніться в repository root. Потім inspect, save, restore і reapply accepted change.

Windows PowerShell — Terminal B

Set-Location (git rev-parse --show-toplevel)
git status --short
git diff -- dashboard
git diff --output="$env:TEMP\day2-dashboard.patch" -- dashboard
Test-Path "$env:TEMP\day2-dashboard.patch"
git restore --staged --worktree -- dashboard
git status --short
git apply "$env:TEMP\day2-dashboard.patch"
git diff -- dashboard

Ubuntu/Linux — Terminal B

cd "$(git rev-parse --show-toplevel)"
git status --short
git diff -- dashboard
git diff --output=/tmp/day2-dashboard.patch -- dashboard
test -s /tmp/day2-dashboard.patch && echo "patch saved"
git restore --staged --worktree -- dashboard
git status --short
git apply /tmp/day2-dashboard.patch
git diff -- dashboard

Після git restore refresh browser і підтвердьте повернення baseline. Після git apply refresh ще раз і підтвердьте KPI = 6 та follow-up filter = 2. Saved patch є recovery source для цієї вправи — відновлювати accepted changes з пам’яті не потрібно.

8. Підготуйте starter до Дня 3

Поверніться в repository root, перейдіть у starter/, підготуйте Python environment і створіть .env лише якщо він ще не існує.

Windows PowerShell

Set-Location (git rev-parse --show-toplevel)
Set-Location workshops\ai-agents-defence-education\starter
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe verify.py
if (-not (Test-Path .env)) { Copy-Item .env.example .env } else { Write-Host ".env exists; not overwritten" }
git check-ignore -v .env

Ubuntu/Linux

cd "$(git rev-parse --show-toplevel)/starter"
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python verify.py
[ -f .env ] || cp .env.example .env
git check-ignore -v .env

Редагуйте local .env у VS Code і додайте власний Groq key тільки туди. Ніколи не вставляйте key у ChatGPT, workbook, screenshots чи shared chat. Якщо є час, запустіть Uvicorn і перевірте /api/health; це перевіряє local application health, а не credential validity і не є Day 3 agent evidence.
