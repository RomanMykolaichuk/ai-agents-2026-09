1. Почнемо з одного питання: що змінюється, коли ШІ може діяти?

Мовна модель може генерувати текст. Корисне agentic application додає навколо моделі мету, bounded context, дозволені tools або actions, limits, evidence про те, що реально відбулося, і точку, де людська відповідальність залишається явною.

Generate

«Поясни це поняття». Модель генерує текст на основі prompt і context.

Recommend

«Порадь, яке джерело варто переглянути». Система пропонує дію, але не виконує її.

Act through a tool

«Прочитай дозволену learning card і використай її для короткої підказки». Application може виконати allow-listed read-only tool і повернути result моделі.

Стартове питання: який із трьох прикладів потребує від application чогось більшого, ніж генерація тексту? Які нові ризики з’являються, коли software може діяти?

2. Від ШІ до великої мовної моделі

Artificial intelligence

Широка категорія систем для задач, пов’язаних зі сприйняттям, прогнозуванням, мовою, міркуванням або вибором дій.

Machine learning

Поширений спосіб створення AI systems через навчання закономірностей на даних замість явного програмування кожного правила.

Generative AI

Моделі, що створюють новий контент — текст, код, зображення або аудіо — на основі статистичних закономірностей і поточного input.

Large language model

Генеративна модель, спеціалізована на мові та пов’язаних представленнях. Вона генерує імовірні продовження з context, але сама по собі не є source of truth, workflow чи авторизованим actor.

Чому корисна відповідь усе одно може бути неправильною

LLM оптимізована для створення правдоподібного output, а не для гарантування, що кожне твердження підтверджене approved source. В освіті це важливо: добре написане пояснення все одно може містити unsupported fact, вигадане citation або надмірно впевнений висновок.

3. Model, chatbot, assistant та agent — це різні рівні

Model

Inference engine. Перетворює input context на output.

Chatbot

Розмовний interface навколо моделі. Керує messages і показує responses.

Assistant

Продукт, який допомагає користувачу виконувати tasks, часто з files, context, browsing або іншими capabilities. У цьому воркшопі ChatGPT Plus використовується як browser-based explanation і coding assistant.

Agentic application

Application задає моделі явну role і boundaries, дозволяє запитувати approved actions/tools, спостерігає results і продовжує controlled workflow.

Практичний тест: «Чи може система щось зробити?»

Якщо система лише генерує текст, називати її «agent» може бути малоінформативно. Різниця стає корисною, коли application може обрати дозволену action, виконати її за правилами, отримати result і продовжити або зупинитися.

Цього недостатньо

Role prompt, довга відповідь, personality, ланцюжок повідомлень або слово «agent» в interface.

Agentic signal

Controlled action selection, tool execution, observation of results, explicit limits і traceable evidence.

Автономність не є самоціллю

Більша autonomy не означає автоматично кращий результат. В освіті вузький та inspectable agent часто легше обґрунтувати, ніж високоавтономний.

4. Мінімальна анатомія освітнього агента

1 · Goal / instruction
Що agent має право та повинен підтримувати
2 · User request
Learner або instructor просить допомогу
3 · Context
Поточна задача, bounded history і дозволена інформація
4 · Model
Інтерпретує request і обирає next step
5 · Tool / action
Необов’язкова approved operation
6 · Observation
Application отримує tool result
7 · Response / stop
Модель відповідає або workflow завершується
8 · Human control
Review, intervention і відповідальність залишаються явними

Agent loop

Think → Act → Observe → Continue or Stop. Цей loop корисний лише тоді, коли кожна action обмежена. У workshop starter модель може запросити один approved read-only tool, application виконує його, записує factual evidence і повертає result моделі.

Tools — це capabilities, а не магія

Tool — це операція, яку application відкриває моделі. Вона може бути вузькою, наприклад «прочитати одну approved learning card», або значно потужнішою: змінити calendar, надіслати message чи оновити database. Ризик змінюється разом із capability.

Read-only tool

Нижчий operational impact. Приклад: отримати один approved course material за fixed identifier.

Write/action tool

Вищий impact. Приклад: щось надіслати, змінити, опублікувати або видалити. Такі actions зазвичай потребують сильніших permissions і approval.

Tool boundary

Модель не повинна отримувати arbitrary file, URL або system access лише тому, що вона це попросила.

Context — не те саме, що long-term memory

Context — інформація, доступна для поточного reasoning step: user request, bounded history, instructions і tool results. Memory — необов’язковий application mechanism, який зберігає інформацію між interactions. Workshop starter використовує bounded context; persistent learner memory для нього не потрібна.

5. Де агенти можуть допомогти у військовій освіті

Наведені приклади є освітніми та адміністративними. Вони не потребують реальних operational data чи autonomous military decision-making.

Guided learner support

Learner спочатку пише власну спробу. Agent читає один approved learning source і дає коротку підказку, не замінюючи роботу слухача.

Instructor preparation

Agent може підготувати draft activity plan з approved course material, а instructor перевіряє pedagogy і final content.

Evidence-bound Q&A

Agent відповідає лише з визначеного набору public або approved training materials і прямо повідомляє, якщо source недостатньо.

Course workflow support

Agent може допомагати структурувати routine non-sensitive tasks, наприклад перевірку submission за explicit checklist, залишаючи final judgement викладачу.

Коротка демонстрація лише викладачем

  1. Показати підготовлений Day 3 starter на instructor machine.
  2. Надіслати один grounded request, для якого потрібна approved learning card.
  3. Показати різницю між текстом model і factual execution log.
  4. Показати call read_course_material і fixed material identifier.
  5. Зупинитися. Не перетворювати Day 1 на participant agent setup або testing.
Що мають помітити учасники: головна зміна не в тому, що «AI звучить розумніше». Application має контрольовану capability, evidence її використання та явну boundary.

6. Human control — це частина architecture

Before

Визначити purpose, allowed data, tools, limits і success criteria.

During

Зберігати actions inspectable, обмежувати permissions, показувати failures і мати stop/recovery path.

After

Перевіряти outputs і logs, тестувати expected failure modes і вирішувати, чи прийнятна system для intended context.

Безпека і межа даних

Використовуйте лише public, synthetic або іншим чином approved material. Не вводьте classified/sensitive information, credentials, API keys, private logs або персональні дані учасників у ChatGPT, learning site, screenshots чи shared support channels.

Перед використанням будь-якого AI service поставте чотири питання: Які дані залишають мій device? Куди вони потрапляють? Що application може зробити? Хто залишається відповідальним?

Практична мета навмисно обмежена: зробити так, щоб Day 2 почався без затримки. Agent runtime сьогодні ще не налаштовуємо й не тестуємо.

Перевірити Python

python --version
Очікується: Python 3.12.x для primary participant baseline. Якщо встановлено іншу версію, її потрібно зафіксувати, а не приховувати різницю.

Перевірити Git

git --version
Очікується: version string Git без command-not-found error.

Перевірити VS Code

code --version
Очікується: version string VS Code. Якщо command code недоступна, але VS Code відкривається нормально, зафіксуйте це як конкретну environment difference.

Перевірити стан repository

git status --short
Очікується: authorised workshop repository доступний локально, видно dashboard/ і starter/.

Перевірка account/access

  1. Підтвердити sign-in до ChatGPT Plus, GitHub і Groq. Не вставляти API keys у цей сайт або ChatGPT.
  2. Переконатися, що authorised workshop repository відкривається у VS Code.
  3. Знайти dashboard/ для Day 2 і starter/ для Days 3–4. Сьогодні їх не змінювати.
  4. Зафіксувати фінальний стан як READY або BLOCKED: <конкретна причина> із next recovery action.
